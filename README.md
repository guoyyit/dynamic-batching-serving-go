# sched：本地推理请求调度与动态批处理

本包提供进程内的多模型推理请求调度与动态批处理能力，计算由本地桩引擎
（`StubEngine`）实现，整条链路不依赖任何外部服务，结果与错误均可在本地复现。

## 1. 架构

```
调用方 ──Submit(ctx, model, payload)──┐
                                      ▼
                 ┌────────── 调度器 Scheduler ──────────┐
                 │  每模型独立队列 (chan *Request)       │
                 │  ┌──────┐ ┌──────┐        ┌──────┐   │
                 │  │ m1队列│ │ m2队列│ ...    │ mN队列│   │
                 │  └──┬───┘ └──┬───┘        └──┬───┘   │
                 │     └────────┼───────────────┘       │
                 │              ▼  feeder（每模型一个）  │
                 │         arrivals（汇总入口）          │
                 │              ▼                       │
                 │         batcher（组批协程）           │
                 │              ▼                       │
                 │         batches（批次通道）           │
                 │      ▼      ▼            ▼           │
                 │   worker  worker  ...  worker（N个） │
                 │              ▼                       │
                 │         Engine.Infer（本地桩）        │
                 └──────────────────────────────────────┘
```

- **多模型共享同一入口**：所有模型共用一个 `Scheduler` 与同一组工作协程，
  但每个模型拥有独立队列通道与独立批处理参数。
- **模型隔离**：某模型队列满时的拒绝/阻塞只作用于该模型的调用方，
  不影响其他模型入队与处理，batcher 与 worker 均不会被单个模型拖垮。
- **协程数量有界**：feeder 数量 = 模型数，batcher 1 个，worker 数由配置固定；
  高压下不会随请求数增长。

## 2. 批处理语义（合并与拆分规则）

批次（`Batch`）是发往工作协程的单元，其确定性规则如下：

1. **按模型分组**：同一批次可以混合多个模型的请求；批次内按模型名排序，
   每个模型一个分组，组内保持 FIFO 到达顺序。
2. **模型分组上限（拆分）**：发往某模型的分组大小不得超过该模型的
   `MaxBatchSize`。当新请求会使该分组超限时，**当前批次立即派发**，
   新请求进入下一批（溢出请求不丢失、不乱序）。
3. **全局上限（拆分）**：批次总请求数达到全局 `MaxBatchSize`（>0 时）立即派发。
4. **批窗口（合并）**：批次从首个请求到达起计时，经过 `BatchWindow` 后派发，
   窗口内到达的请求合并为一批。
5. **请求不可再分**：请求是最小单元，永不被拆成多条；重试时只重试可重试的
   失败成员（部分重试），成功成员不重复执行。
6. **批次不可变**：批次一经派发即只读；组批期间配置更新不影响已锁定的批次。

## 3. 调度规则

### 3.1 组批触发条件（任一即触发）

- 批次从首个请求到达起经过 `BatchWindow`；
- 批次总请求数达到全局 `MaxBatchSize`；
- 某模型分组达到该模型 `MaxBatchSize`。

### 3.2 排队与等待

- 请求提交后进入该模型的有界队列，调用方阻塞等待结论。
- 请求在排队期间超时或被取消：batcher 在组批时检查上下文，**已过期的请求
  不再进入任何批次**，结论为 `ErrTimeout` / `ErrCancelled`。
- 请求已进入批次但尚未执行时超时：工作协程在执行前检查上下文，结论同样为
  `ErrTimeout`，已发生的执行不回滚（调用方超时与执行在途的竞态由上下文判定）。
- **已组批的请求绝不静默丢弃**：批次内每个请求最终都恰好得到一条结论
  （成功 / 失败 / 超时 / 取消 / 关闭）。

### 3.3 并发消费与恰好一次

- 多个 worker 并发消费批次通道；每个请求只属于一个批次、一个分组，
  因此**最多被消费一次**，不存在重复计算。
- 结论通过请求内置的缓冲通道（1 缓冲）恰好一次返还给原调用方，
  调用方提前超时离开也不影响通道写入（不阻塞、不泄漏协程）。

### 3.4 失败与重试

- 引擎对每条请求返回独立结论：成功、可重试失败（`Retryable=true`）、
  永久失败（`Retryable=false`）。
- **部分失败不拖垮整批**：失败成员得到 `ErrEngineFailed` 结论，
  同批其他成员正常成功。
- **重试策略**：仅重试可重试的失败成员，最多 `MaxRetries` 次，
  每次重试间隔 `RetryBackoff`；重试只携带失败成员，成功成员不重复执行。
- **重试不产生重复副作用**：桩引擎对同一请求的多次调用只计一次副作用
  （幂等消费者），调用次数与副作用次数可通过 `Attempts` / `SideEffects` 观测。
- 重试耗尽后给出明确的失败结论（`ErrEngineFailed`）。

### 3.5 背压

队列达到 `MaxQueueSize` 上界时，按模型配置的策略处理：

- `BackpressureReject`：立即拒绝，返回 `ErrQueueFull`（默认策略）；
- `BackpressureBlock`：阻塞等待队列空间，期间调用方超时/取消/调度器关闭
  会立即返回，不会无限阻塞。

## 4. 配置项

### 4.1 全局配置 `Config`

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `BatchWindow` | 批窗口：批次从开始组批起的最长等待时间 | > 0 |
| `Workers` | 并发消费批次的工作协程数 | > 0 |
| `MaxBatchSize` | 单批总请求上限（所有模型合计），0 表示不限 | >= 0 |
| `Models` | 各模型独立参数 | 至少一个模型 |

### 4.2 模型配置 `ModelConfig`

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `MaxBatchSize` | 发往该模型的单批最大请求数 | > 0 |
| `MaxQueueSize` | 该模型等待队列容量（与其他模型隔离） | > 0 |
| `MaxRetries` | 可重试失败的最大重试次数 | >= 0 |
| `RetryBackoff` | 重试退避时长 | >= 0 |
| `Backpressure` | 队列满时的策略：`BackpressureReject` / `BackpressureBlock` | 二选一 |

### 4.3 配置热更新

- `UpdateConfig` 先校验新配置：**校验失败返回错误且保留上一个可用配置**，
  调度不中断。
- 校验通过后配置以原子指针整体切换（带递增版本号）。
- **版本锁定**：正在形成的批次锁定创建时的配置版本，其整个生命周期沿用
  该版本；切换后新形成的批次使用新版本。因此参数更新与组批并发时，
  每个批次都落到某个完整、一致的版本上。
- 模型可新增；移除模型时若其队列仍有未处理请求，更新被拒绝
  （避免请求被静默丢弃）。

## 5. 可观测性

`Metrics()` 返回某一时刻的指标快照（`MetricsSnapshot`）：

- **按模型**：实时队列深度 `QueueDepth`；提交/完成/失败/超时/取消/拒绝/重试计数；
  该模型分组的批大小分布 `BatchSizes`；延迟统计 `Latency`（计数、最小、最大、
  平均与固定延迟桶）。
- **全局**：上述计数的合计、批次总数、整批大小分布、全局延迟统计。
- 延迟单位为毫秒，桶边界固定为
  `1/2/5/10/25/50/100/250/500ms、1/2.5/5s、+Inf`。

## 6. 可区分的错误结论

| 错误 | 触发场景 |
| --- | --- |
| `ErrQueueFull` | 队列满且策略为拒绝 |
| `ErrTimeout` | 排队/执行期间超过调用方截止时间 |
| `ErrCancelled` | 调用方主动取消 |
| `ErrModelNotFound` | 请求的模型未注册 |
| `ErrModelRemoved` | 请求的模型已被移除 |
| `ErrEngineFailed` | 推理失败（重试耗尽或不可重试），`errors.Is` 可判 |
| `ErrShutdown` | 调度器已关闭，请求未及处理 |

## 7. 本地桩引擎

`StubEngine` 不依赖任何外部服务，行为确定：

- 输出为 `模型名:输入回显`；
- `SetFailUntil(reqID, n)`：前 `n` 次调用返回可重试失败，之后成功；
- `SetPermanentFail(reqID)`：永久失败；
- `SetDelay(d)` / `SetGate()`：模拟耗时与门控（用于确定性测试）；
- `Attempts` / `SideEffects` / `Batches`：观测执行次数、副作用次数与组批记录。

## 8. 测试

`go test -race ./...` 覆盖：动态组批、批窗口拆分、模型分组上限、
混合模型同批、多模型隔离、超时/取消区分、并发消费恰好一次、失败重试与
幂等副作用、部分失败、背压拒绝与阻塞、配置热更新与版本锁定、可观测性、
未知模型、关闭排空、高压下协程数有界。
